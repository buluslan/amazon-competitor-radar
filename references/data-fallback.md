# data-fallback · 数据提取与兜底

> 本文件是五步流程的数据侧细则：每步要什么字段、什么时候拉、拉不到怎么办。判断逻辑（圈词/聚合/定性/打分/分析）在 SKILL.md 各步，这里只管数据。
> 数据源原则：**字段级描述需求，不绑定服务商**——任何能供出下表字段的亚马逊数据工具（MCP）都能跑。下文以卖家精灵为例的映射已实测，换数据源时按字段对照。

---

## 一、依赖总规律

- **取数**动作用数据 MCP；**判断**动作（圈词分类/重叠聚合/看图定性/打分/分析）不需要任何外部数据，纯推理。
- 图片下载不需要 MCP：亚马逊图片 CDN（m.media-amazon.com）无鉴权，curl 直接下。
- 流程起点数据（反查流量词、词下商品）是刚需：环境没有能供这两项的数据工具时**停下如实告知**，不做无数据的降级版。①的核心词清单支持用户手贴（从反查工具导出或自行整理），但②起必须数据源——词下商品没法手贴。

## 二、每步字段需求表

| 步 | 需要什么 | 字段 | 已实测的映射（卖家精灵） |
|---|---|---|---|
| ① 反查圈词 | ASIN 的流量词表 | 词 / 月搜索量 / 流量占比 | `traffic_keyword`：一次调用全出（searches / trafficPercentage 直出）。`keyword_order` 可作交叉参考（无流量占比直出，份额藏在每词头部 ASIN 明细里） |
| ② 搜词聚合 | 每个核心词的词下商品列表 | ASIN / 标题 / 图 URL / 价格 / 评分数 | `traffic_keyword` 开 `includeTop10AsinData=true`：每词带词下自然位前排商品列表（标题/图/价格/评分数；自然位排名是列表口径说明，不进交付物）。**注意：词下列表约 10 个、无上架时间**——对最终入池候选批量调商品详情补 |
| ③ 看图分类 | 主图图片文件 | 主图 URL → 下载 | ②的词下商品列表自带图 URL，③直接用，不必另调。我的基准图用 `asin_detail` 的 imageUrl |
| ④ Listing 打分 | 两边完整 Listing | 标题 / 五点 / 价格 / 上架时间 / 评分数 | `asin_detail`：title / features / price / ratings / availableDate 一次全出 |
| ⑤ 竞品分析 | 深拆数据 | 完整 Listing / 评论（尽量 100 条含差评）/ 价格与促销 / 销量或排名趋势 | `asin_detail`（Listing+促销）/ `review`（评论）/ `asin_prediction`（销量趋势），缺哪项标 [缺失] |

## 三、已验证的接口事实（换数据源/环境需复核）

以下接口事实以 BILITOK 自动卷发器 B0D66W5CQ2（US 站）验证：

1. **`traffic_keyword` 是①②主力接口**：传我的 ASIN 一次返回它的流量词（词表可达数百个，分页取），每词自带月搜索量、**流量占比（trafficPercentage）直出**；开 `includeTop10AsinData=true` 后每词附带**词下自然位前排商品列表**（约 10 个/词：ASIN/标题/图 URL/价格/评分数/自然位排名）——①的词表和②的词下商品都靠它。
2. **查词下商品时关键词参数是模糊匹配**：传"curling iron"返回的是相关词列表，精确词不一定在其中（首次调用可能没有精确词，加 order 按搜索量降序重试可排到第一）——②逐词调用后要**从返回里人工挑精确匹配项**，别把相关长尾词的商品列表当成核心词的。
3. **词下列表不含上架时间**：②对最终入池候选（15-20 个）批量调 `asin_detail` 补 availableDate，不要对全部词下商品拉详情（按需提取，候选被踢掉多少就少拉多少）。
4. **用户自己的 ASIN 必然混在数据里**：反查每词的头部 ASIN 明细里有用户自己（实测每个词都在场）；词下列表若用户链接在首页也会含自己。②聚合前必须剔除用户 ASIN 及其同父变体（剔除与变体识别规则见 SKILL.md 第②步执行 2）。
5. **反查词表会混入泛匹配词和小语种词**：实测出现"curl machine"（词下头部其实是健身弯举机）和西语词。①做品类词/场景词分类时，对这类字面撞车但场景不同的词，在分类理由里注明并建议用户剔除——它们进②会捞回一堆无关候选。
6. **`keyword_research` 的关键词过滤在实测环境中失效**：无论传种子词还是精确词表，都返回全库无关词（完全不相干的品类）。**不要用它当主力接口**；若环境里只有它，先小规模试一次过滤是否生效再决定。
7. **`keyword_order` 无流量占比直出**：每词的点击/转化份额藏在头部 ASIN 明细（约 3 个/词）里；顶层 ASIN 字段返回 null。仅作交叉参考。
8. `asin_detail` 含 availableDate / ratings / price / title / features / imageUrl / zoomImageUrl——**仅主图一张**，对③三分类够用。`review` 的 rating 字段可能全返回 null——星级筛选靠 starList 参数分桶拉取（1-3 星差评/4-5 星好评各拉一桶）。
9. m.media-amazon.com 图片 CDN 无鉴权，curl 直接下载成功。

## 四、数据提取时机（按需不囤）

| 数据 | 提取时机 | 用途 | 兜底 |
|---|---|---|---|
| 流量词表 | ① | 圈核心词 | 无兜底——流程起点数据，缺了走不了。用户能手贴词表跳过反查，但只覆盖① |
| 词下商品列表 | ②（随流量词一次带出） | 重叠聚合出候选池 | 同上。查询失败的词如实标注，不静默跳过 |
| 价格 / 评分数 | ②（词下列表自带） | 候选池初筛参考 | ④拉详情时自动补全 |
| 上架时间 | ②末（对入池候选批量拉详情） | 候选池参考+④阶段维度 | 词下列表无此字段，必须补拉 |
| 主图 URL | ②（词下列表自带） | ③下载对比 | 我的基准图用 asin_detail；某候选图缺失 → 开 amazon.com/dp/ASIN 商品页提取主图（备胎，单页静态内容已实测稳定） |
| Listing 字段（标题/五点/价格/上架时间/评分数） | ④ | 五维度打分 | 不需要兜底——asin_detail 全有 |
| 评论 / 销量趋势 | ⑤ | 四板块分析 | 评论缺失 → 标 [缺失] 降级为三板块（联网抓评论要翻页+碰反爬，不稳定，不硬抓）；销量趋势缺失 → 跳过该板块 |

## 五、图片获取方式（③专用）

1. **获取**：②的词下列表已带每个候选的图 URL；我的基准图从 asin_detail 取。
2. **下载**：curl 下载到会话临时目录，文件名含 ASIN（如 `/tmp/competitor-radar/B0XXXX.jpg`），下载完即可对比。
3. **查看**：优先用运行环境的读图能力（Claude Code 用 Read 工具直接读图）。**部分环境 Read 读图只返回 URL 不进上下文**——此时改用环境里支持远程图片 URL 的视觉分析工具；CDN 签名含 `==` 或 `//` 时部分视觉工具报 400，重新生成 URL 可绕过。视觉分析对关键判断（同方案/跨方案分界处的候选）做一次交叉验证（换第二个视觉工具或重新生成 URL 复核）——单轮视觉输出偶有串图幻觉。环境完全没有读图手段时的降级处理见 SKILL.md 第③步执行 4。
4. 图片下载失败或模糊无法判断：标 [待定] 并注明原因，交人工。

## 六、调用纪律

- **一次一词**：逐词查询时不要把多个词拼接成一个参数传入（实测逗号拼接会被当成一个词查询）。
- 失败如实标注：某个词查询失败，在交付物里单独列出，涉及它的统计口径注明——不允许静默跳过。
- 调用配额意识：按需提取不囤数据（见上表时机列）；②只对入池候选补拉详情，不对全部词下商品拉。
- 只读不写：全程不碰任何写操作类工具。
